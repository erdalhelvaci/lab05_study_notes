# ADR-001: Error Handling and Authentication Flow in AuthRepository

**Date:** 11 Nov 2026  **Author:** Erdal Helvacı  **Milestone:** Lab 5
**Tool and model used:** Antigravity (Gemini 3.8 Flash)

## Context
In Lab 5 Part 2, we needed to implement authentication operations (`signIn`, `signUp`, `signOut`) and translate raw Firebase exception codes into clean, user-friendly error messages. The UI layer needs to consume uniform `AuthFailure` exceptions with specific human-readable messages rather than dealing with raw Firebase SDK exception objects.

## Prompt
```
Implement signIn and signUp in AuthRepository such that:
- Email is trimmed before sending to FirebaseAuth
- FirebaseAuthException is caught and wrapped in AuthFailure(messageFor(e.code))
- messageFor maps known error codes ('invalid-email', 'weak-password', 'email-already-in-use', 'invalid-credential', 'wrong-password', 'user-not-found', 'network-request-failed') using a modern Dart switch expression.
```

## Result
```dart
  Future<void> signIn(String email, String password) async {
    try {
      await _auth.signInWithEmailAndPassword(
        email: email.trim(),
        password: password,
      );
    } on FirebaseAuthException catch (e) {
      throw AuthFailure(messageFor(e.code));
    }
  }

  static String messageFor(String code) {
    return switch (code) {
      'invalid-email' => 'The email address is not valid.',
      'weak-password' => 'The password must be at least 6 characters.',
      'email-already-in-use' => 'An account already exists for this email.',
      'invalid-credential' || 'wrong-password' || 'user-not-found' => 'Wrong email or password.',
      'network-request-failed' => 'No connection. Check your network.',
      _ => 'Sign-in failed. Please try again.',
    };
  }
```

## Rejected suggestion(s) — at least one
The AI initially suggested using generic `catch (e)` blocks to catch all `Exception` types and wrap them into `AuthFailure('Unknown error')`. This was rejected because catching generic exceptions would mask programming errors (such as `TypeError` or missing arguments) and violates the lab requirements which specify catching `FirebaseAuthException` specifically. Any other unexpected errors should be allowed to propagate or be handled properly by Flutter error handlers.

## Verification
Verified through automated unit tests in `test/lab05_test.dart` and `test/own_test.dart`:
- Verified `messageFor` returns accurate messages for all specified Firebase error codes.
- Verified `MockFirebaseAuth` simulates failure with `FirebaseAuthException` throwing `AuthFailure` with the expected friendly message.
- Ran `flutter test` and passed all test cases.

## What I learned
Dart's switch expression syntax (`||` patterns with exhaustive matching) produces concise and maintainable mapping code. Wrapping vendor-specific SDK exceptions in domain-specific exceptions keeps UI components completely decoupled from Firebase specifics.
